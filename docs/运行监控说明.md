# 运行监控说明

## 可访问端点

后端只开放以下 Actuator HTTP 端点：

- `GET /actuator/health`：整体健康状态。Redis 暂时不可用时可能显示 `DOWN`，用于观察依赖状态。
- `GET /actuator/health/liveness`：进程存活探针，只判断应用自身是否仍可运行。
- `GET /actuator/health/readiness`：接流量探针，检查应用状态与 MySQL；不把可降级的 Redis 缓存纳入就绪条件。
- `GET /actuator/info`：应用名称与版本。

健康详情与组件明细关闭。`env`、`beans`、`configprops`、指标等其他管理端点不通过 HTTP 暴露。当前管理端点和游戏 API 使用同一服务端口；健康探针仅返回聚合状态，不返回数据库地址、账号、口令、Redis 密码或内部组件明细。

部署平台应将存活检查配置为 `/actuator/health/liveness`，就绪检查配置为 `/actuator/health/readiness`。不要用根健康端点替代就绪检查，否则可选 Redis 故障会让平台错误地摘除仍能提供核心服务的实例。

## Redis 本机开发

应用通过 `REDIS_HOST`、`REDIS_PORT`、`REDIS_DATABASE`、`REDIS_PASSWORD` 读取 Redis 连接配置，默认连接本机 `127.0.0.1:6379`。本机开发无需为 Redis 开放 Windows 防火墙入站规则。排行榜 Redis 仅作短期缓存，MySQL 仍是玩家和游戏数据的唯一事实来源。

## 验证

运行隔离 H2 健康端点集成测试：

```powershell
cd springboot-backend
mvn -Dtest=ActuatorHealthEndpointIntegrationTest test
```

测试会把 Redis 指向本机未使用的端口来模拟缓存不可用，不会修改真实 Redis 或玩家数据库。
